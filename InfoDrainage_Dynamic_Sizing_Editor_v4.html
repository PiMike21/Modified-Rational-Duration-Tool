XML safeguards

Checks performed before export.
  • InfoDrainage root: uploaded XML must contain an InfoDrainage root.
  • Numeric values: blank, non-finite, negative, or overflowed values are rejected before any edit is committed.
  • Scope: only Modified Rational (Static) catchment RMDetails/@TC, its direct manual ToCCalculator/@TC, and existing DurAdFactorPair/@DurationOfPeak / @AdjFactor values can be changed.
  • Duration / ToC coupling: every Duration of Peak edit automatically creates the matching Dynamic ToC edit for that catchment. A single catchment cannot have multiple different pending edited duration values because it has only one Dynamic ToC.
  • Text-preserving export: the original UTF-8 IDDX text is used as the output base. The app replaces only the exact attribute-value spans selected for editing; it does not serialize or rewrite the rest of the XML.
  • Local processing: the model is parsed and modified in the browser; it is not sent to a server by this page.
